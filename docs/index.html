Ask from your phone.
Your board writes its own code.

Open the board's page and say "make the LED breathe". A small bridge on your computer hands the request to the AI program you already use (Claude Code, Codex, OpenCode, Pi, Grok Build), which writes MicroPython, runs it on the board, reads the errors and fixes them. No API keys and no model settings.

Flash an ESP32-S3 Source code

Web flasher

Two steps, in Chrome or Edge on a computer, with the board plugged in by USB. Nothing is installed on your computer.

This browser cannot talk to USB devices. Use Chrome or Edge on Windows, macOS, Linux or ChromeOS. Phones and Firefox/Safari do not support Web Serial. You can also flash from a terminal: see the quick start.

  1. 1

    Install MicroPython

    For ESP32-S3 with octal PSRAM (for example N16R8 or N8R8 modules). This erases the whole board.

    Other ESP32 boards: install MicroPython for your chip from micropython.org, then do step 2. If the board is not found, hold BOOT while plugging it in. When it finishes, close the window before step 2.

  2. 2

    Copy openTARS

    Copies the system to a board that already runs MicroPython. Run it again later to update: your settings, chats, skills and programs stay.

    ✓ Done. The board restarts.

  3. 3

    Connect

    1. On your phone, join the open Wi-Fi opentars-xxxx and open http://192.168.71.1.
    2. In Settings > Wi-Fi, pick your network. The page shows the new address.
    3. On the computer with the AI program, paste the command the page shows:
    curl -fsS http://<board>/bridge.py -o bridge.py && python3 bridge.py http://<board>

The page has no password: anyone on your Wi-Fi can use it. Use it on a network you trust.

Raspberry Pi, Orange Pi and other Linux boards

No flashing needed: the same system runs in the board's own Python 3, with shell commands and GPIO through libgpiod. Run these on the board, over SSH.

Then open http://<board>:8080. Tested only on an x86 Linux PC standing in for a board; not yet on a real ARM board.

git clone https://github.com/project-opentars/OpenTARS_ESPSelfProgramming
cd OpenTARS_ESPSelfProgramming && sbc/install.sh
sbc/install.sh --hardware   # GPIO and I2C access, uses sudo, then reboot

openTARS Pi and Gargantua Pi

Planned, not released

Separate from Self-Programming: a lean edition of the openTARS assistant made for single-board computers, with its own small model. Nothing here is built or measured on a board yet, and there is no release date.

openTARS Pi

  • For ARM64 boards with Linux (Raspberry Pi OS, Armbian, Ubuntu). Reference board: Orange Pi Zero 2W with Armbian, command line only.
  • Command line and an optional background service, off until you turn it on.
  • Installs in your home folder without sudo and removes with one command.
  • No windows, voice, photo editing or image generation: it says so and points to the full app.
  • GPIO through the Self-Programming board library. Writing to a pin always asks for approval on the board.
  • Optional server for your local network: listens only on the board by default, needs a token, and approvals appear on the board itself.

Gargantua Pi

  • A new model smaller than Gargantua 2 Lite, in two sizes: about 400 MB and about 250 MB. The installer picks the one your board can run.
  • Four tools: terminal, web search (through SearXNG), remember and forget.
  • Short conversations in English and Portuguese. No vision.
  • Downloaded from Hugging Face (OpenTARS) with a SHA-256 check.
  • When a request is too much for it, it can suggest a bigger Gargantua on your network, only if you choose.
